# 瀚渤智慧工地

面向施工项目的人员、班组、定位人脸考勤与报表管理小程序，一级普通工人到五级超级管理员的功能均已实现并部署到测试服务器。

文档：

- [项目总文档](docs/项目总文档.md)：一级到五级每项功能的用法、业务规则、代码位置和验收要点，以及跨级规则、数据模型、部署运维、已知问题。给写需求、做验收的同事看。
- [功能总览与实施计划](docs/功能总览与实施计划.md)：需求范围、进度和验收顺序。
- `docs/superpowers`：三至五级的规划与实施记录（2026-11）；`docs/design/ui-redesign`：界面设计稿。
- `docs/archive`：早期设计稿、旧计划和二级验收清单，只作历史留存。

工地人员与考勤管理系统，采用 pnpm monorepo：

- `apps/miniprogram`：Taro 4.2、React、TypeScript，支持微信小程序与 H5。
- `apps/api`：NestJS、Prisma、PostgreSQL，提供登录、身份绑定、项目人员、打卡安排、考勤、补卡、安全信用、报表和平台管理接口。
- `packages/domain`：角色权限与考勤规则，两端共用。

工人流程：**微信登录 → 完善资料 → 邀请码绑定档案 → 填写用工资料 → 拍摄本人底照 → 进入项目**。底照经管理员审核后，打卡按 **选择项目 → GPS 范围校验 → 现场照片 → 确认本次安全交底 → 活体与底照比对 → 提交考勤** 执行。

### 一级 · 普通工人

权限范围：本人资料、本人任务与已加入的项目。

| 模块 | 功能 |
| --- | --- |
| 登录入场 | 长期／临时用工入口；微信登录、头像昵称、真实姓名、手机号及邀请码绑定；六位码加入临时任务 |
| 用工登记与底照 | 身份证、住址、紧急联系人、健康、保险及银行卡分步填写；录入底照，查看审核状态，驳回后换照 |
| 首页与项目 | 下一次打卡、今日打卡点、待办提醒、本月出勤／工时／缺卡、首页公告；我的项目（地址、考勤范围、班组、负责人，可导航拨号） |
| 打卡 | GPS 范围校验 → 现场照片 → 安全交底确认 → 活体人脸比对 → 保存考勤；加班进场／退场 |
| 我的任务 | 查看工作安排、确认班组交底；临时任务开工／完工打卡，按实际分钟计工，跨夜拆分 |
| 考勤与补卡 | 按项目看本人记录和缺卡；异常日期一键申请补卡（带入项目、日期与未打卡时点）；开工／完工补卡；审批进度 |
| 安全信用 | 查看本人分数和违规明细，对已确认违规申诉 |

### 二级 · 班组长

权限范围：本班组及下属工人。

| 模块 | 功能 |
| --- | --- |
| 班组首页 | 本班到岗、缺卡、待审批；数字可点进当日班组考勤 |
| 工作安排 | 选本班在场工人发布任务；修改、追加或撤下人员、完成或取消；套用历史模板；提醒漏打开工 |
| 临时工邀请 | 按姓名手机号生成六位专属邀请码，可作废；完工后确认退场 |
| 打卡安排 | 给下属班组或个人设打卡次数、时间、宽限和工作日，最早次日生效，历史不改 |
| 补卡审批 | 待审批／已处理；只能批职级低于自己的人，不能批本人 |
| 班组考勤 | 日／周／月报，点人看逐日明细，月报导出 Excel |
| 班组安全 | 发布当天交底（可套用前一天）、看确认名单；登记隐患并整改关闭；登记违规（进入待复核） |
| 班组日报 | 自动汇总任务、临时人员、实际出勤、交底和隐患；保存、回读、复制 |

### 三级 · 项目管理员

权限范围：本项目全部班组。

| 模块 | 功能 |
| --- | --- |
| 项目首页 | 今天应到／到岗／未到；补卡、违规、底照三类待办 |
| 项目人员 | 分页筛选；新增、编辑工种、班组、身份、暂停、退场；任免班组长（不能任免其他项目管理员）；从其他项目复用人员或发调人申请 |
| 用工资料 | 查看原文并标“已核实”或“需更新”，每次查看留记录 |
| 班组与邀请 | 新建班组、改负责人、看组长变更；生成和撤销档案邀请码；“班组现场”可替组长操作该班组的全部页面 |
| 审核 | 底照审核；违规复核与申诉处理 |
| 工时规则 | 项目类型、午休、加班起点，按生效日期分版本 |
| 考勤报表 | 日／周／月报，可按班组或组长筛；人员逐日明细；0–100 项目评分；导出 Excel |
| 项目设置与记录 | 项目资料、联系人、地图选考勤范围；项目操作记录 |

### 四级 · 公司管理员

权限范围：本公司全部项目，可“进入项目”使用三级全部页面。

| 模块 | 功能 |
| --- | --- |
| 公司首页 | 全公司今天到岗／缺卡、待办、进行中项目 |
| 项目 | 公司项目列表；新建项目（至少一名管理员，可直接录入新人）；改项目状态（暂停、完工）；各项目一览（待复核、待审底照、资料待核实、低信用等） |
| 人员 | 公司人员一人一行、服务端筛选；项目负责人；人员任职与离岗；任免项目管理员；审批调人申请 |
| 补卡审批 | 多一组“需要你批”，标出只有你能批的申请 |
| 公司设置 | 默认打卡安排和默认工时规则（新建项目时套用）；公司资料；查看信用规则 |
| 报表与记录 | 公司日／周／月报及导出；公司操作记录 |

### 五级 · 超级管理员

权限范围：全平台。只能在服务器上用命令开通或撤销。

| 模块 | 功能 |
| --- | --- |
| 平台首页 | 公司数、进行中项目、在用账号；没有管理员的公司、管理员未绑定、只有你能批的补卡 |
| 公司 | 新增、搜索、修改公司（含名称和信用代码）；任免公司管理员（选已有账号或录入新人发邀请码）；进入公司；暂停／恢复公司（暂停后只读） |
| 账号 | 按手机号、姓名查账号和全部身份；停用账号立即下线，可恢复 |
| 平台设置与规则 | 首页公告、平台联系电话；发布安全信用规则新版本 |
| 平台日志 | 全平台操作记录，可按公司、类型、操作人筛 |

### 通用规则

- 五级权限逐级继承；授权范围为全平台 ⊃ 公司 ⊃ 项目 ⊃ 班组；一个人可在同一项目兼任多个职级。任免职级要求操作人职级严格更高；任何人不能审批本人的补卡。
- 工时按有效打卡计分钟，展示正常／加班／未分类小时；扣午休、跨夜拆分、重叠去重；不折算工日，无单独加班审批。未配置工时规则的历史记录保留为未分类，不反推加班。
- 安全信用：同一工人跨公司一份，初始 100 分；一般／严重／重大违规扣 5／10／20 分，须上级复核；累计 10 个无违规实际工作日恢复 5 分。
- 报表统一“项目 → 人员 → 逐日明细”，含分类工时、临时工标记、项目评分和安全分；Excel 另含安全记录和打卡位置。

## 本地运行

需要 Node.js 22、Corepack、Docker 和微信开发者工具。

```bash
git clone https://github.com/Ludan-daye/hanbo.git
cd hanbo
corepack pnpm install --frozen-lockfile
cp .env.example apps/api/.env
docker compose -p hanbo-local up -d postgres
corepack pnpm --filter @construction/api prisma:generate
corepack pnpm --filter @construction/api exec prisma migrate deploy
corepack pnpm --filter @construction/api exec prisma db seed
corepack pnpm --filter @construction/domain build
corepack pnpm --filter @construction/api build
corepack pnpm --filter @construction/api start:local
```

启动前编辑 `apps/api/.env`：设置独立的 JWT 密钥、微信 AppID / AppSecret 和服务端腾讯云 API 密钥。其他配置项见 `.env.example`。Docker Compose 中的数据库账号仅供本地开发。

动作活体使用腾讯云 `GetActionSequence` 和 `LivenessCompare`，设置 `TENCENT_FACE_MODE=VIDEO_ACTION`、`FACE_DEV_STUB=false`。底照和新录制的视频在核验时发送至腾讯云，不需要身份证照片、H5 RuleId 或原生一闪 SDK。

可选的演示数据可在本地数据库中通过 `corepack pnpm --filter @construction/api seed:dev` 初始化；其中账号和人员均为演示资料。

## 小程序构建与手机测试

将 `apps/miniprogram/project.config.json` 中的 `appid` 设置为自己的小程序 AppID，保持后端运行。日常开发直接使用源码项目，不必反复生成 ZIP：

```bash
corepack pnpm dev:weapp --api-base-url http://YOUR_COMPUTER_LAN_IP:3000
```

在微信开发者工具中打开 `apps/miniprogram`，只需导入一次；`project.config.json` 已指向 `dist-weapp/`。保持上述命令运行，保存源码会自动重新编译，开发者工具读取同一个目录。手机预览点击工具中的“预览”；手机与电脑须在同一 Wi-Fi，使用有开发者或体验权限的微信扫码。电脑 IP 改变后用新地址重启该命令。

### 云端测试

测试 API：`https://162.14.74.2`，健康检查为 `/health`。服务器运行 API、PostgreSQL 和持久文件目录，已迁入本地测试数据。手机连接云端时可使用移动网络，后端不依赖 Mac 开机。微信测试号通过预览使用，手机需在右上角菜单开启调试以跳过域名校验；正式发布前再配置域名、备案和合法域名。

```bash
# Automatically rebuild the Mini Program against the test API.
corepack pnpm dev:weapp --api-base-url https://162.14.74.2 --test-login

# Upload the current backend source, back up data, migrate and restart.
corepack pnpm deploy:test ubuntu@162.14.74.2
```

SSH 密码只在终端提示时输入。更新命令使用当前工作区源码，不自动提交 Git，也不上传 `.env` 或覆盖云端数据。前端改动保存后自动编译；本人日常联调可在微信开发者工具打开“真机调试 → 自动真机调试”，选择手机系统，保持手机微信前台运行且登录工具显示的同一账号。当前采用局域网模式，手机与电脑需在同一 Wi-Fi。点击“编译并自动调试”（Mac：⇧⌘R）更新手机调试代码，无需每次生成预览码；是否连接成功以工具显示为准。预览包仍是当次编译的快照；后端改动执行部署命令。

测试包登录页列出六个测试账号：五个职级各一个（`dev-worker`、`dev-team`、`dev-project`、`dev-company`、`dev-system`），另有不在任何项目里的临时工 `dev-worker-2`，用来走临时工邀请。点击即可进入，无需口令。正式微信登录仍保留。`--test-login` 仅控制客户端入口；服务端必须显式配置 `DEPLOYMENT_ENV=test` 和 `TEST_LOGIN_ENABLED=true`，并执行 `pnpm exec tsx --env-file=.env prisma/seed.test-logins.ts` 补齐已有的六个 `dev-*` 账号资料（含没有项目的临时工 `dev-worker-2`）。该脚本不创建权限，也不修改真实微信账号；不要为此重跑完整开发种子。默认部署关闭测试登录，生产环境禁止开启。服务端 Nginx 对测试登录单独限流。项目人员加入仍使用原邀请码。

部署配置位于 `deploy/test`，当前服务器目录为 `/opt/hanbo-test`：`current` 指向代码版本，`.env` 存放独立服务端配置，`uploads` 保存图片和 Excel。API 只监听本机 3000，数据库不映射公网端口，Nginx 提供 HTTPS。首次部署需要准备独立 `.env`、数据库、上传文件、Nginx 和证书，`deploy:test` 用于已初始化的服务器。

超级管理员只能在服务器上用命令开通或撤销（小程序里不能任免、停用超级管理员），只接受已绑定、正常的管理人员账号，最后一位不能撤销，每次都记操作记录。在 `/opt/hanbo-test/current` 下执行：`sudo docker compose --env-file /opt/hanbo-test/.env -f deploy/test/compose.yaml run --rm -T --no-deps api node dist/system/system-admin.cli.js grant --phone 13800000000`（`revoke --phone …` 撤销，`list` 列出）。本地用 `corepack pnpm --filter @construction/api system-admin list`。

`hanbo-cert-renew.timer` 每天检查两次短期 IP 证书续期，成功后重载 Nginx；`hanbo-backup.timer` 每天 03:30（服务器 Asia/Shanghai 时区）备份数据库、文件和加密配置到同机 `backups`。更新前也自动备份，备份目录仅管理员可读。异地备份、告警和正式容量压测仍待配置。

需要交给其他电脑时才生成独立导入包：

```bash
corepack pnpm package:weapp --api-base-url http://YOUR_COMPUTER_LAN_IP:3000
```

导入命令输出的整个项目文件夹；产物保存在本地 `项目对接`，不纳入版本控制。导入包是生成当时的快照，不会随源码自动更新。

使用正式小程序账号上传平台时，在开发者工具点击“上传”，填写版本号和说明，再到小程序后台的版本管理设置体验版。代码变更仍需构建并重新上传，自动编译不能直接更新已上传的版本。供手机长期、异地使用前，须把 API 与数据库部署到云端，使用稳定的 HTTPS API 地址，并配置 request／uploadFile／downloadFile 合法域名；上传客户端不会部署后端。

微信小程序中进入“我的 → 人脸档案”，提交本人底照后可点击“开始活体人脸测试”，按随机顺序完成张嘴、闭眼动作。页面显示服务端确认的核验结果、相似度和云端请求编号。正式考勤仍要求底照审核通过和有效排班。

仅查看前端演示时运行 `corepack pnpm --filter @construction/miniprogram build:h5:demo`，产物在 `apps/miniprogram/dist`；浏览器演示不替代小程序真机活体核验。

## 验证

```bash
corepack pnpm test
corepack pnpm --filter @construction/api typecheck
corepack pnpm --filter @construction/miniprogram exec tsc --noEmit
corepack pnpm --filter @construction/api test:face:video
```

`test:face:video` 使用独立的本地 PostgreSQL schema，验证 HTTP、权限、持久化和并发处理，腾讯云边界由测试替身提供。真实核验需另用手机调用已开通的腾讯云服务，可能产生调用费用。

源码仓库不包含 `.env`、数据库内容、用户照片、视频和本地上传文件。已有云端 HTTPS 测试服务；正式上线还需完成容量验收、域名备案、微信合法域名及隐私声明配置，并完成小程序审核发布。
